# hobby 詳細ページの外部リンクは OGP カードにする

- Status: Accepted
- Date: 2026-10-19

`externalUrl` を素のテキストリンクで出すと、リンク先の名前と中身が読者に伝わらない。カードにするには og:title / og:description / og:site_name / og:image が要る。

- **画像は自ドメインから配る**: CSP は `img-src 'self' data: blob:` のままで、外部画像を直リンクしない。取得した画像はビルド時に webp 化して `/_astro/` 配下に出す
- **取得はビルドから切り離す**: 初版はビルド時にリンク先を fetch していたが、`opengraph.githubassets.com` は匿名アクセスに rate limit（100 req/window・IP 単位）をかけていて 429 を返す。Astro の `inferRemoteSize` はその 429 で `FailedToFetchRemoteImageDimensions` になり、`fetchOgp` の catch が画像なしカードに落とすため、**画像が黙って欠けたまま deploy される**（ローカル再現: web-speed-hackathon / type-quest / chemoinformatics の3件が 429 で画像なし、他は成功）。取得元の都合でビルド成果物が変わる状態をやめ、`bun run ogp:update` で作る `src/data/ogp.json` + `src/assets/ogp/` のスナップショットを build が読む
- **同期はビルドで機械的に守る**: snapshot に無い `externalUrl` があると `getOgp` が例外を投げて build が失敗する。画像なしカードが静かに出ることはない
- **画像が無いカードは失敗ではない**: `og:image` を持たないリンク先（例: emoemoji）は画像なしのカードになる

却下した案:

- **クライアント側で fetch して描画**: 実行時 JS とサードパーティへの CORS 依存が増える。zero-JS 方針に反する
- **og:image を直リンク**: `img-src` に任意の https を足すことになり、CSP の意味が無くなる
- **外部の OGP 取得 API / サービス**: 依存先が増えるだけで、rate limit と可用性の問題は移るだけ
- **ビルド時 fetch + retry だけ**: 429 の `Retry-After` が 15 分単位になることがあり、ビルド時間が取得元の都合に振り回される。待たずに諦めれば画像欠けは残る
- **取得失敗を警告だけで通す**: 画像やカードが黙って欠ける経路を残すことになる。snapshot に無い URL は build を失敗させ、実行時の fallback は `og:image` を持たないリンク先（画像なしカード）に限る

トレードオフ: 画像（約 750KB）を repo に持つことと、リンク先の og:image が変わっても自動では追従しないこと。更新は `bun run ogp:update` を手で回す。ホスティング先の可用性・rate limit に build が左右されなくなる方が、静的サイトとしては優先。
