# deploy を cf へ移す

- Status: Accepted
- Date: 2026-11-11

[2026-10-21 の ADR](2026-10-21-deploy-は-wrangler-のまま-cf-は-API-操作に限る.md) では、adapter 無しの静的 build が `.cloudflare/output/v0/` を作らず `cf deploy` が通らないため wrangler に残した。今回 `@astrojs/cloudflare` 15.0.0-beta.5（`@cloudflare/vite-plugin` 2.0 beta を使う）と `cf` 1.0.0-beta.27 を入れ、`cf migrate --bundler vite` で `cloudflare.config.ts` を作り、`cf build` → `cf deploy --prebuilt --mode production --dry-run` が通ることを確認したので、build・deploy を `cf` へ移す。`wrangler.jsonc` と `wrangler` 依存は削除した。

動機は deploy token の権限を絞ること。`cloudflare.config.ts` に `accountId` を書くと、token にアカウント探索用の Account Settings Read・Memberships Read が要らなくなり、Workers Scripts Edit と wwwyo.dev の Workers Routes Edit だけで deploy できる見込み（apps.wwwyo.dev の deploy token と共用）。

- adapter は既定で `SESSION`（KV）と `IMAGES` の binding を足す。静的サイトには不要で、残すと deploy token に KV・Images の権限が要り KV の auto-provision も走るため、`session: false` と `imageService: "compile"`（従来どおり build 時に sharp で変換）で止めた。dry-run の binding は `env.ASSETS` だけ、upload する Worker コードは 0 KiB
- 出力は旧 `dist/` と同じ 136 ファイル。差分は CSS の minify 結果（vendor prefix の追加など）と、adapter が `_headers` に `/_astro/*` の immutable Cache-Control を足すこと
- `cf` 1.0.0-beta.28・29 は `bunfig.toml` の `minimumReleaseAge`（7日）を満たさないため beta.27 を固定した

前提とリスク: adapter 15・`cf`・vite-plugin 2.0 はいずれも beta で、Build Output の形式も stable 前に変わりうる。main merge = 即 deploy なので、更新時は CI の `cf deploy --dry-run` の結果を見てから merge する。壊れたら、この変更の revert で wrangler の deploy に戻せる（`wrangler.jsonc` と `deploy` script が戻る）。
